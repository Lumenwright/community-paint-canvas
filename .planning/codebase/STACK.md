# Technology Stack

**Analysis Date:** 2026-04-06

This is a pnpm monorepo with two packages: `web/` (SvelteKit EBS + drawing site + overlay) and `extension/` (Twitch Extension panel, not yet scaffolded on this branch). The web package is the active build target; the extension directory is planned but currently empty.

---

## Languages

**Primary:**
- TypeScript 5.x — all source files in `web/src/`; strict mode enabled (`"strict": true` in `web/tsconfig.json`)

**Secondary:**
- SQL — Supabase migration files in `supabase/migrations/`
- HTML/CSS — embedded in Svelte single-file components

---

## Runtime

**Environment:**
- Node.js 24.14.1 (current runtime on dev machine; no `.nvmrc` pinning)

**Package Manager:**
- pnpm (workspace root `pnpm-workspace.yaml` defines `extension` and `web` packages)
- Lockfile: present (`pnpm-lock.yaml`)
- Notable pnpm config: `onlyBuiltDependencies: [esbuild, supabase]` in root `package.json`

---

## Frameworks

**Core:**
- Svelte 5.x (`svelte: "^5.0.0"`) — component framework, uses runes syntax
- SvelteKit 2.x (`@sveltejs/kit: "^2.0.0"`) — full-stack framework; file-based routing under `web/src/routes/`
- Vite 6.x (`vite: "^6.0.0"`) — dev server and bundler, configured via `web/vite.config.ts`

**Testing:**
- Vitest 2.x (`vitest: "^2.0.0"`) — test runner; integration test suites live in `web/tests/`
- Run commands: `pnpm test` (single run via `vitest run`), `pnpm test:watch` (watch mode)

**Build/Dev:**
- `@sveltejs/vite-plugin-svelte` 5.x — Svelte/SvelteKit integration for Vite
- `@sveltejs/adapter-vercel` 5.x — Vercel deployment adapter; outputs to Vercel serverless/edge functions

---

## Key Dependencies

**Critical:**
- `@supabase/supabase-js` 2.x — Supabase client; used for both server-side DB access (service role) and client-side Realtime subscriptions (anon key). Two separate client instances: `web/src/lib/server/supabase.ts` and `web/src/lib/client/supabase.ts`
- `jose` 5.x — JWT signing and verification; handles Extension JWTs (HS256), handoff tokens (60s TTL), and session cookies (7d TTL). No external auth server dependency — all JWT operations are self-contained

**Infrastructure:**
- `supabase` CLI 2.84.4 — local Supabase stack management (`pnpm db:start` / `pnpm db:stop`). Installed as a workspace dev dependency and invoked via explicit binary path in root `package.json` scripts

---

## Configuration

**TypeScript:**
- `web/tsconfig.json` extends `.svelte-kit/tsconfig.json` (auto-generated by SvelteKit)
- Strict mode on; `allowJs`, `checkJs`, `sourceMap`, `resolveJsonModule` enabled
- Module resolution handled by SvelteKit's generated tsconfig

**Build:**
- `web/vite.config.ts` — minimal config, only the `sveltekit()` plugin
- `web/vercel.json` — defines a single Vercel Cron job: `*/1 * * * *` → `GET /api/cron/expire`
- No additional Vite aliases or custom plugins beyond SvelteKit defaults

**Environment:**
- SvelteKit `$env/static/private` and `$env/static/public` for type-safe env access
- Private vars (server-only): `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TWITCH_EXTENSION_CLIENT_ID`, `TWITCH_EXTENSION_SECRET`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `SESSION_SECRET`, `BROADCASTER_TWITCH_ID`, `CRON_SECRET`
- Public vars (client-safe): `PUBLIC_SUPABASE_URL`, `PUBLIC_SUPABASE_ANON_KEY`, `PUBLIC_EBS_URL`, `PUBLIC_DRAWING_SITE_URL`, `PUBLIC_DEV_MODE`
- See `web/.env.example` for all required keys

**Local Supabase:**
- Ports shifted to `44xxx` range (`supabase/config.toml`) to avoid Windows Hyper-V excluded port range (54274–54373)
- Local Studio at `http://127.0.0.1:44323`; API at `:44321`; DB at `:44322`
- Postgres major version 15; analytics disabled

---

## Platform Requirements

**Development:**
- Docker Desktop (required for local Supabase via `pnpm db:start`)
- Node.js, pnpm
- `web/.env` populated from `web/.env.example`

**Production:**
- `web/` deploys to Vercel (adapter-vercel); serverless functions for all API routes
- `extension/` (when built) deploys to Twitch CDN as a static bundle
- Database: Supabase cloud (Postgres + Realtime)
