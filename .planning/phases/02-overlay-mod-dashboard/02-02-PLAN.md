**web/src/routes/(auth)/mod-login/+page.server.ts:**

This file has TWO exports:

1. A `load` function that checks if the user already has a valid mod/broadcaster session. If so, redirect to `/mod` immediately (no need to re-login). Also pass through any `error` query param from failed callback attempts.

```typescript
import { redirect } from '@sveltejs/kit';
import type { PageServerLoad, Actions } from './$types.js';
import { TWITCH_CLIENT_ID } from '$env/static/private';
import { MOD_REDIRECT_URI } from '$lib/server/twitch-oauth.js';

export const load: PageServerLoad = async (event) => {
  const session = event.locals.session;
  if (session && (session.is_mod || session.is_broadcaster)) {
    throw redirect(303, '/mod');
  }
  return {
    error: event.url.searchParams.get('error')
  };
};
```

2. A `default` form action that initiates the PKCE flow:

```typescript
export const actions: Actions = {
  default: async (event) => {
    const state = crypto.randomUUID();
    event.cookies.set('oauth_state', state, {
      path: '/',
      httpOnly: true,
      sameSite: 'lax',
      maxAge: 60 * 10,
      secure: false // localhost dev; production uses secure: true via SvelteKit adapter
    });
    const params = new URLSearchParams({
      client_id: TWITCH_CLIENT_ID,
      redirect_uri: MOD_REDIRECT_URI,
      response_type: 'code',
      scope: 'user:read:email',
      state
    });
    throw redirect(302, `https://id.twitch.tv/oauth2/authorize?${params}`);
  }
};
```

**web/src/routes/mod/settings/+page.server.ts:**

Broadcaster-only auth guard using redirect. Load initial settings and moderator list server-side (these don't change rapidly like the queue, so SSR is fine):

```typescript
import { redirect } from '@sveltejs/kit';
import type { PageServerLoad } from './$types.js';
import { db } from '$lib/server/supabase.js';

export const load: PageServerLoad = async (event) => {
  const session = event.locals.session;
  if (!session || !session.is_broadcaster) {
    throw redirect(303, '/mod-login');
  }

  // Load current settings
  const { data: settingsRows } = await db.from('settings').select('*');
  const settings: Record<string, unknown> = {};
  for (const row of settingsRows ?? []) {
    settings[row.key] = row.value;
  }

  // Load active moderators
  const { data: mods } = await db
    .from('moderators')
    .select('twitch_user_id, username, added_at, active')
    .eq('active', true)
    .order('added_at', { ascending: true });

  return {
    username: session.username,
    settings,
    moderators: mods ?? []
  };
};
```

| Browser -> /api/review, /api/settings, /api/moderators, /api/canvas/reset | Session cookie auth; API routes already have guards from Phase 1 |

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-2-01 | Elevation of Privilege | /mod page | mitigate | `+page.server.ts` load checks `session.is_mod \|\| session.is_broadcaster`; redirects to /mod-login if false. API routes have separate `requireMod()` guards. |
| T-2-02 | Elevation of Privilege | /mod/settings page | mitigate | `+page.server.ts` load checks `session.is_broadcaster` only; redirects to /mod-login if false. API routes `PATCH /api/settings` and `/api/moderators` have `requireBroadcaster()` guards. |
| T-2-03 | Spoofing | PKCE login flow | mitigate | `oauth_state` cookie (randomUUID, httpOnly, 10min TTL) validated in mod-callback before token exchange. Prevents CSRF on OAuth initiation. |
